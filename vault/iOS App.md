# iOS App

[[Home]] · [[App Store/Release Checklist|Release Checklist]]

## What it is

A universal iPhone + iPad app (`TARGETED_DEVICE_FAMILY = 1,2`) built with [Capacitor 8](https://capacitorjs.com). Capacitor wraps the production web build (`dist/`) in a native WKWebView app. The web files are **copied into the app bundle**, there is no `server.url`, so:

- the app works fully offline (Airplane Mode included);
- it never contacts any server, ours or anyone else's;
- the strict Content-Security-Policy from `vite.config.ts` still applies inside the app.

## What differs from the website

All in `src/native.ts`, `src/ui.ts` and the end of `src/style.css`. On the website none of it runs.

- **Saving.** A download link does nothing inside an app. `saveFile()` instead writes the file to the app's Documents folder and opens the share sheet. Because `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` are on, that folder shows up in the Files app as *On My iPhone/iPad › HackerPDF*. Name clashes get ` (2)`, ` (3)`… Cancelling the share sheet is fine; the file is already saved. Toasts say "Saved …" instead of "Downloaded …".
- **Safe areas.** Toolbars, the home screen and the back button pad themselves with `env(safe-area-inset-top)` (the Dynamic Island / status bar), and tool screens keep their last row above the home bar. In a normal browser tab these insets are 0, so the website looks exactly as before.
- **Native feel.** No text-selection callouts or tap flashes on buttons.
- **Links.** Any external link (for example in a converted Word file) opens in Safari, never inside the app. Capacitor does this by default.

## Native project files worth knowing

- `ios/App/App/Info.plist` — display name, `arm64`, `ITSAppUsesNonExemptEncryption = NO` (see [[App Store/Privacy and Data Security#Export compliance (encryption)]]), Files-app sharing, Productivity category.
- `ios/App/App/PrivacyInfo.xcprivacy` — Apple's privacy manifest: no tracking, no collected data, file-timestamp API used only inside the app container (reason `C617.1`).
- `ios/App/App/Assets.xcassets` — 1024 px app icon and the launch screen (light and dark).
- `ios/App/CapApp-SPM/Package.swift` — generated by Capacitor; don't edit.

## Commands

```bash
npm install
npm run ios        # build the website, copy it into the app, open Xcode
npm run ios:sync   # same, without opening Xcode
```

After any change to `src/`, run `npm run ios:sync` before building in Xcode, or the app keeps the old web files.

## Continuous build

`.github/workflows/ios.yml` runs on every push to `main` (and `feat/ios-*` branches) that touches the app. On a macOS 26 runner it compiles the app for real devices and for the simulator with the default Xcode 26, then installs and launches it on an iPhone Pro Max and an iPad Pro 13" simulator and uploads a launch screenshot of each as the **simulator-screenshots** artifact. The first run (Xcode 26.6) compiled cleanly for both.

## Decisions

- **Capacitor, not a rewrite.** The tools are ~15,000 lines of TypeScript that already work in Safari. Bundling them keeps one codebase and identical behaviour.
- **Bundled, not remote.** Loading the live website would break offline use, make the privacy promise depend on the network, and is the pattern App Review most often rejects under guideline 4.2 (minimum functionality).
- **iOS 16.4 minimum.** The OCR engine needs WebAssembly under a CSP with `'wasm-unsafe-eval'` (Safari 16+), and the styles use `color-mix()` and `dvh` units (Safari 16.2+). 16.4 still covers iPhone 8 and later.
- **Save to Files + share sheet** rather than share sheet only, so a dismissed sheet never loses work, and every saved file is findable later.
- **No status-bar plugin.** The app follows the system light/dark setting, so iOS picks the right status-bar colour on its own.
- **Not yet:** opening a PDF *into* HackerPDF from another app's share sheet ("Open in…"). It needs native document-type handling plus a small bridge into the tools; a good 1.1 feature.
